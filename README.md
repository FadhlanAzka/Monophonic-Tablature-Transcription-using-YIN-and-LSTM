# YINTAB

Monophonic tablature transcription using YIN pitch detection and an LSTM string-fret mapper.

## Requirements

- Python 3.10 or newer is recommended.
- FFmpeg is recommended for robust audio loading through `librosa`.
- FluidSynth is optional and only needed to render generated MIDI files to WAV.
- Demucs is optional and only needed for the HTDemucs preprocessing helper.

## Install

Create and activate a virtual environment, then install Python dependencies:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

Optional Demucs support:

```powershell
python -m pip install demucs
```

## Default Configuration

The web application reads defaults from `config.py`.

| Setting | Default | Environment variable |
| --- | --- | --- |
| Token index CSV | `tokens/token index v2.csv` | `YINTAB_TOKEN_INDEX_CSV` |
| LSTM model | `models/optuna.jit` | `YINTAB_MODEL_PATH` |
| SoundFont | `assets/FluidR3_GM.sf2` | `YINTAB_SOUNDFONT_PATH` |
| Results directory | `static/results` | `YINTAB_RESULTS_DIR` |
| Device | `auto` | `YINTAB_DEVICE` |
| FluidSynth binary | `fluidsynth` from PATH, then legacy Windows path | `YINTAB_FLUIDSYNTH_BIN` |
| Render sample rate | `44100` | `YINTAB_RENDER_SAMPLE_RATE` |
| Flask host | `0.0.0.0` | `YINTAB_FLASK_HOST` |
| Flask port | `5000` | `YINTAB_FLASK_PORT` |
| Flask debug | `true` | `YINTAB_FLASK_DEBUG` |
| Pitch mode | `yin` | `YINTAB_PITCH_MODE` |
| Pitch confidence threshold | `0.0` | `YINTAB_PITCH_CONFIDENCE_THRESHOLD` |
| Sequence tab optimizer | `false` | `YINTAB_TAB_OPTIMIZER` |
| Fret distance cost | `0.15` | `YINTAB_TAB_COST_FRET_DISTANCE` |
| String change cost | `0.25` | `YINTAB_TAB_COST_STRING_CHANGE` |
| Large shift cost | `0.5` | `YINTAB_TAB_COST_LARGE_SHIFT` |
| Large shift threshold | `5` | `YINTAB_TAB_LARGE_SHIFT_THRESHOLD` |
| Open string cost | `0.0` | `YINTAB_TAB_COST_OPEN_STRING` |
| Position preference cost | `0.0` | `YINTAB_TAB_COST_POSITION` |
| Preferred fret | `5.0` | `YINTAB_TAB_PREFERRED_FRET` |

Relative paths in environment variables are resolved from the project root.

## Run Web App

```powershell
python app_web.py
```

Open:

```text
http://localhost:5000
```

Upload a WAV file. Results are written to `static/results/<run_id>/` by default.

## Outputs

Each run can produce:

- CSV note and tablature mapping.
- ASCII tablature text.
- MIDI file.
- Optional rendered WAV from MIDI.
- Visualization image.
- `manifest.json` for the web result page.

CSV outputs include timing columns when generated by the current pipeline:

- `start_time`
- `end_time`
- `duration`
- `frame_count`
- `segment_source`
- `onset_aligned`
- `pitch_mode`
- `pitch_confidence`
- `octave_corrected`
- `mapping_decoder`

MIDI generation uses these timing columns when present. Older CSV files without timing columns are still supported with fixed-step timing.

Segmentation uses pitch changes as the default note boundary and can split repeated same-pitch notes when onset detection indicates a new attack. Current defaults are defined in `app.py`:

- `MIN_NOTE_DURATION_SEC = 0.08`
- `MIN_REST_DURATION_SEC = 0.08`
- `ONSET_SPLIT_TOLERANCE_SEC = 0.035`

Pitch detection defaults to the historical YIN pipeline. Set `YINTAB_PITCH_MODE=pyin` to use `librosa.pyin`, which provides voiced probability as `pitch_confidence`. YIN mode uses a finite-pitch confidence proxy, so default output remains backward compatible.

Tablature mapping defaults to the historical per-frame argmax decoder. Set `YINTAB_TAB_OPTIMIZER=1` to enable Viterbi-style decoding over pitch-valid LSTM logits with playability costs for fret distance, string changes, large shifts, open strings, and preferred fret position. Pitch mask constraints are still applied before optimization.

## Architecture

The shared inference flow lives in `core_pipeline.py`:

- `PipelineConfig` describes input paths and runtime options.
- `PipelineArtifacts` describes generated output paths.
- `run_transcription_pipeline()` runs audio loading, beat/onset analysis, pitch pipeline, LSTM mapping, CSV/TAB/MIDI output, and visualization.

`app_web.py` and `app_gui.py` are wrappers around this shared function, with UI-specific behavior limited to upload/dialog handling, result pages, optional player display, and optional MIDI-to-WAV rendering.

## Notes

- Missing model or token index files stop startup with a clear error.
- Missing FluidSynth or SoundFont only disables MIDI-to-WAV rendering; CSV, tab, MIDI, and visualization can still be generated.
- The project currently targets monophonic guitar melodies, not chords or polyphonic audio.

## Evaluation Metrics

Evaluation scripts keep the existing token-classification metrics and add music-facing metrics when token mapping data is available:

- `note_accuracy` / `midi_accuracy`
- `pitch_accuracy_50_cent`
- `mean_abs_pitch_error_cent`
- `string_accuracy`
- `fret_accuracy`
- `string_fret_joint_accuracy`
- `mean_abs_string_error`
- `mean_abs_fret_error`
- `tablature_edit_distance`
- `tablature_edit_similarity`

Current evaluation scripts operate on token windows, so event-level onset precision/recall/F1 are reported as unavailable in `summary.json` until a future event-level evaluator is added.

## Tests

Run the focused unit and smoke tests with:

```powershell
python -m pytest
```

The current tests cover note normalization, MIDI conversion, token index loading, pitch mask construction, sustain collapse, ASCII tab rendering, and a monkeypatched smoke run of the shared transcription pipeline.
